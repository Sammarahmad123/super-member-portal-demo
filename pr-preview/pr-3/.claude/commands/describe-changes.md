# Describe Changes

You are helping with test maintenance. The user changed this app and tests in the test repo are failing.

Your job: read the latest changes in THIS repo and write a short structured file that lists only the changes tests would care about. This file is called the "change manifest."

Arguments (optional): $ARGUMENTS
- If the user passed a git range (e.g. `HEAD~3..HEAD` or a commit hash), use it.
- If no arguments, default to `HEAD~1..HEAD` (the last commit). If unclear, ask.

## Steps

1. Show the user `git log <range> --oneline` so they can confirm which commits are included.
2. Run `git diff <range>` and read it.
3. From the diff, list only the things tests would notice:
   - Renamed or removed `data-testid` values
   - Renamed or removed `id` values used by tests
   - Renamed HTML file paths or routes
   - Changed visible text on buttons, headings, labels, table cells, dropdown options
   - Removed elements or pages
   - New elements or pages
   - Behavior changes (a button now does something different)

   Ignore: CSS-only changes, comments, README, internal refactors that don't change the user-facing surface.

4. Write the manifest to `maintenance/app-change-manifest.md` using this exact format:

   # App Change Manifest

   **Date:** <today, YYYY-MM-DD>
   **Commit range:** <from..to>
   **Branch:** <current branch>
   **Generated by:** /describe-changes

   ## Summary

   One short paragraph in plain English.

   ## Renamed testids

   | Old | New | File |
   |-----|-----|------|

   ## Renamed pages / routes

   | Old | New |
   |-----|-----|

   ## Renamed visible text

   | Where (page + element) | Old | New |
   |------------------------|-----|-----|

   ## Removed elements / pages

   - <list, or "None">

   ## New elements / pages

   - <list, or "None">

   ## Behavior changes

   - <list, or "None">

   ## Unrelated changes (ignored)

   - <list, or "None">

   ## Notes / uncertainty

   - <anything unclear, or "None">

5. Show me a short summary in chat (3-5 lines). Do not paste the whole file.

## Rules

- If a section has nothing, write "None". Never leave blank.
- Only list what you can confirm from the diff. Do not invent.
- Read-only task. Do not edit source code.
- If the diff is too big or unclear, ask which files or range to focus on. Do not guess.
